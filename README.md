# K10 Studio · UV-K10 Pro Web 写频工作台

一个面向 **泉盛 UV-K10 Pro / K8 协议、参考固件 ENG 8.02.16** 的浏览器写频项目。可以离线整理信道与广播存台，也可以通过浏览器设备接口建立编程会话、读取配置、验证正常密码、审阅差异并写入回读。

这是已经包含界面、数据编解码、传输、恢复流程和测试的独立项目。**目前尚未连接真实电台验收，不将合成设备测试或原指令仿真称作实机可用保证，也不宣称已经完全替代官方 App/CPS 的所有功能。** 已证范围和剩余差异见下表。

- 固件与硬件逆向仓库：[guanzi008/uv-k10pro-firmware](https://github.com/guanzi008/uv-k10pro-firmware)
- 本仓库：[guanzi008/uv-k10pro-web](https://github.com/guanzi008/uv-k10pro-web)
- 运行方式：静态网页，无服务器账户、无上传接口、无第三方运行时脚本。
- 数据边界：设备配置位于外部 NOR；**不能把 MCU 的 `publish.bin` 当作信道备份**。

## 开始使用

需要 Node.js 22 或更高版本。启动页面不需要安装 npm 依赖：

```sh
git clone https://github.com/guanzi008/uv-k10pro-web.git
cd uv-k10pro-web
npm start
```

在同一台电脑打开 **http://127.0.0.1:4173**。设备 API 要求安全上下文，通常使用 HTTPS 或浏览器认可的本机 localhost；不能把另一台机器的 localhost 当作自己的工作台地址。

首次打开没有设备数据。可以先点“载入演示工作区”检查各项功能：演示数据由本项目生成，明确标记为合成数据，不是工厂镜像或推荐发射配置。页面中的 Si4732/BK1080 切换是不同能力的编辑视图，不会把电台上的接收芯片改成另一颗。

### 连接、读取、编辑、写入

1. 点“连接设备”，核对机身是 **UV-K10 Pro** 并勾选型号确认。USB ID、固件字符串及参数版本都不能独立充当唯一机型证明。
2. 桌面优先使用 Web Serial；默认采用当前 CPS 的 38400、8N1、无流控，另可选择 115200。浏览器会让用户自行选择端口。
3. HELLO 握手会按当前主机时间同步电台 RTC，连接窗口已说明这一实际效果。若设备配置了密码，输入当前密码完成正常认证；失败不会猜测或自动重试。
4. 点“读取设备”，建立**本次连接**的基线。当前读取 16 个配置区，共 93,996 B；不存在把未读地址填 FF 后冒充完整转储的行为。
5. 编辑信道、存台、设置或其他记录。所有改动先留在本地工作区，可随时导出 `.k10` 项目。
6. 打开“写入预览”查看地址、修改前后字节和区域名称。确认后先保存本地恢复快照、重新核对全部待写地址，再逐块写入和回读验证。
7. 写入后需要电台重新加载配置时，在连接日志中显式发送重启命令。读取不会自动重启；重启命令没有应答，页面不会把“已发送”描述成“已确认硬件重启”。

断开或重新连接后，旧工作区不能继续以旧会话身份写设备。重新读取建立新基线，然后把备份中双方已覆盖的可写配置区合并进去，再审阅差分。

## 尚未作完整替代声明的部分

以下限制不是隐藏的空按钮，涉及未确认语义的区域会被明确拒绝写入，仍可保存在项目备份中：

- **实机 USB、蓝牙和写入验收**。原指令仿真没有模拟完整板卡、USB 电气、BLE 链路、RF 接收和真实 NOR 时序。
- **BK1080 的实际硬件版本**和 **K10 专属 BLE 服务/特征 UUID**。APK 内多机型共存的字符串不足以建立本型号的 GATT profile。
- **BFO 的有符号/单位转换**。CPS 存储是 UInt16，显示检查却含负数区间；目前只编辑原始 16 位数值，避免造出未经证明的 Hz 语义。
- **频段边界**采用本样本的实际消费者与当前已读计划，不套用其他产品的频段表。CPS 的 160 B 紧凑读路径与其 272 B 序列化槽距不一致，本项目遵循独立确认的固件 272 B 槽距；详细规则见 [bands.md](docs/bands.md)。
- **保护凭据修改**。正常登录已实现，但 `0x17000..0x18FFF` 的受保护写流程没有开放；不提供工程密码、解锁绕过或自动重试。
- **NOAA SAME** 只发现未进入当前 K8 活跃编程流程的残留类型，不虚构存储地址；已实现两版 K8 配置中的 NOAA 静噪与手动/自动搜台。官方专有项目文件格式仍未作为裸 NOR 猜测导入。
- **CSV 的固有缺项和版本冲突**：官方 22 列没有完整属性、步进或保留区；CPS 的三项调制和参考固件的四项调制并不一致。

功能边界分别见 [协议](docs/protocol.md)、[存储和广播证据](docs/radio-memory.md)、[CPS CSV](docs/cps-csv.md)、[硬件归属](docs/hardware-profile.md)。

## 备份与恢复

### `.k10` 是首选工作区格式

项目格式同时保存原始基线、当前编辑值、覆盖区间、SHA-256 和写入日志。未读字节没有真实数据，不会混入分段导出。导入文件中的型号字符串、来源标签或伪造会话标识**不能赋予设备写权限**。

裸 NOR 文件只接受 2 MiB 或 4 MiB；2 MiB 明确作为部分覆盖。识别到 Cortex-M 向量头的应用固件会拒绝导入。设备虽报告为 25Q32 / 4 MiB，当前编程 handler 的地址限制仍独立存在，因此在线读取配置后不会开放伪造的“4 MiB 全片备份”下载。

### 写前持久化和失败处理

写前将完整 `.k10` 快照提交到浏览器 IndexedDB；提交失败就不开始设备写入。最多保留最近 5 份。备份页可“载入最近恢复快照”，以离线方式查看原始基线和待写编辑，不自动回滚硬件。

整批待写地址会在首次写入前重新读取，必须与基线一致。每块成功回读后才更新该块基线；后续失败时保留已验证进度，把结果不确定的块记入日志并停写。后续应重新连接/读取，不能把浏览器错误提示当成设备完全没有变化。

协议层也实现了样本 `>=0x50000` 写模式的完整 4 KiB 扇区备份、合并重写和整扇区核对，但工作台默认只操作已确认的配置区，不提供任意高地址编辑器。

## CSV 使用方式

- **本项目无损信道 CSV**：每条记录保存 64 B 原始十六进制及独立属性；名称和频率列用于阅读，与原始字节必须一致。在工作台编辑，或选择官方列格式做表格编辑。
- **广播 CSV**：明确声明 `chip`、`band` 和 `record`。记录 0 为 VFO，不能与预置台 1 混淆。原始 8 B 记录保留 mode/BFO/保留字节。
- **官方 CPS 22 列**：按官方列顺序解析 UTF-8 或中文编码。必须有按序完整 999 行，因为官方导入器按行位置定位，不能依赖 No. 列恢复稀疏/重排文件。旧版含 MSW 的 20 列会拒绝。
- DCS 按八进制处理；CPS 扫描 raw 0..31 对应列表 1..32，32 为全部，255 为无。
- 固件 SSB/CW、非 CPS 亚音、异常属性等无法可靠写回官方 CPS 的记录，拒绝官方 CSV 导出；使用 `.k10` 或无损 CSV。

## 开发与验证

页面本身只有本地 ES modules，静态构建不联网。JSDOM 是开发测试依赖，不会打入网站。

```sh
npm ci
npm run check
npm test
npm run build
```

`dist/` 可部署到提供 HTTPS 的静态主机。默认不含站点发布或公开仓库权限变更。不要把个人备份文件放入静态目录。

CI 执行同样的语法/模块/分发检查、Node 测试和构建，并生成静态站点构建产物。测试覆盖：编解码保真、编码与精度边界、CSV/项目往返、图像页格式、流式拆包、CRC/XOR、认证、超时取消、写前备份、错误 ACK、访问门控返回零、跨扇区恢复、浏览器适配器 fake API，以及基于模拟 DOM 的真实页面事件流程。

DOM 测试不是浏览器视觉截图，也不是设备验收。本轮云浏览器与执行器不共享 localhost，未通过该地址完成视觉验收。

### 可选：执行官方原指令的参考实验

厂商固件、APK、EXE、DLL、完整私有 schema 和原始反汇编不进入本仓库。普通测试只使用合成数据和必要的少量结果向量。自行取得正确样本后，可以运行：

```sh
# 需要研究仓库的 Unicorn 依赖及用户自行取得的官方明文固件
python tests/reference/replay-radio.py /path/to/stock.raw.bin \
  --research-tools /path/to/uv-k10pro-firmware/tools \
  --output /path/to/radio-replay.json

# 参数与依赖见脚本 --help 及 docs/protocol.md
python tests/replay_auth.py --help
```

广播参考证据包含 24 组真实 ARM 调用，正常密码认证包含 6 组 x86 MAC + ARM AES 接受/拒绝及正常配置密码分支。所有替代的硬件边界和未模拟的部分在文档中列明。

## 硬件补充：4898

机主本轮补充音频功放标识为 **`4898`**。本项目按用户报告记录，并未从这四位数字唯一确认厂商、前后缀、封装、使能脚或电路连接，**不擅自命名为 LM4898**。音频功放不建立 Si4732/BK1080 的存台布局，也不新增独立写频区。
