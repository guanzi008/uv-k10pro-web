# K8 设置与数据覆盖清单

本清单把 UV-K10 Pro 对应 K8 配置中的 **27 个顶级表**逐项映射到本项目实现。它核对数据与设置覆盖，不将“有 JSON 声明”视为已经确认的设备行为，也不以此声称全部传输、硬件或 App 服务均已实机验收。

参考材料是 `QUANSHENG-1.1.0-64.apk` 与 68 包中的 K8 资产、UV-K10 Pro 0.56 PC 客户端，以及 ENG 8.02.16 固件。APK 的发布入口、样本哈希及 K8 绑定证据见 [BLE 证据](ble-profile.md)。未复用 K82 或其他型号的地址和枚举。原 APK、EXE 及完整厂商 JSON 不在此仓库中分发。

## 额外设置与边界

普通设置元数据当前包含 **141 个字段：138 个可编辑、3 个状态只读**。这些数字只统计 `SETTINGS_FIELDS`，不包括信道、VFO、广播、频段组、联系人、消息、开机图，以及专用密码流程。状态字段是 `0x19002` 遥毙、`0x19003` 加密通话标志和 `0x1B000` 功率扩展标志。

新增普通写入切片为：

| 地址与长度 | 用户设置 | 已证转换 |
|---|---|---|
| `0x19001`, 1 B | 空口写频发送次数 | 1..4；stock 无效输入回退 2；修改次数不开始发射 |
| `0x1900A`, 1 B | 信道重配置策略 | 0 正常，1 禁止重配置，2 禁止重配置及发射；stock 大于 2 回退 0 |

两者存在于 K8 资产、PC 当前隐藏参数转换器以及 stock 配置装载器。标签和语义来自本型号 PC 的列表及字段，不从其他机器借用。

`0x1B000` 的值 0/1 被固件读取至 RAM `0x2000030C`。PC 程序读取并保存该字节，但在 `wfm_hide_param_Load` 中明确隐藏其控件；其写函数 `06000501` 没有调用者。Web 将它列为只读状态及文件备份内容，不将不存在的正常 PC 操作扩展为普通功率开关。

## 这轮消除的未知项

- **BFO 的符号及 Hz 单位**：已由本型号原指令连接到 Si 接收器属性 `0x0100`，34 组重放证明 signed 16-bit、向零归整到 10 Hz。详见 [BFO 证据](bfo.md)。
- **A/B 开机显示选择**：PC `060002EB / 060002EC` 实际构造 999 个普通信道和 7 个本侧 VFO；编辑只接受 0..1005，并保留历史选择字节。
- **信令时间**：K8 标注秒/毫秒，PC 转换器直接保存对应数字。没有把选项序号误乘某个来自其他型号的时基。
- **DTMF/5Tone 分隔与组码**：单符号字段不再允许误写两位代码；联系人、上线/下线码各自使用其专属字符约束。
- **App 实时功能**：恢复 K8 手填位置/RTC 同步及 APRS 消息发送；stock 另有 `0x02E1` 被动接收通知。独立 codec、App 转换限制、会话失效要求及 24 组原指令验证见 [实时功能](live-functions.md)。这些功能不属于上面的 27 个参数表，不使用写入 NOR 模拟实时命令。

## 仍需要外部证据的范围

物理 USB/BLE 传输、真实设备回读，以及 RF/音频表现不能由配置资产或函数级 CPU 重放替代。K10 专属 BLE GATT 的新恢复证据与仍需实机验证的部分见 [BLE](ble-profile.md)；当前整体边界见 [验证](validation.md)。

SAME 的残留 PC 类型尚未发现进入本 K8 活跃写频路径，不分配猜测地址。遥毙状态、加密标志和板卡身份等不明行为保持原始备份，不能因其出现在资产中就宣称已掌握完整控制语义。
