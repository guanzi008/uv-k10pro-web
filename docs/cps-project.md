# 官方 CPS 0.56 的 DAT 文件

`src/core/cps-project.mjs` 实现 UV-K10 Pro 官方 PC 软件 0.56 的原生 `.dat` 配置文件导入、编辑后导出，以及从完整配置工作区生成 `.dat`。文件支持与实机连接权限分离；导入始终产生离线工作区。

## 官方样本中的实际保存与打开路径

分析对象是已提取的 CPS 程序，SHA-256 为 `79c9b3429187f7fca13cc8971d0e5fd46184f078127f149f333a267b99815132`。

| 方法 | Token / RVA | 已核对的行为 |
|---|---|---|
| 静态初始化器 | `06000453` / `0x6E4E0` | 分配 `880640` 字节，即 `0xD7000` 的 `CpsData` 数组 |
| 保存菜单 | `060003E8` / `0x68B4C` | 文件筛选 `*.dat`；调用 `GetCpsData`；清空目标文件；调用 `BinaryWriter.Write(byte[])` 写完整数组 |
| 配置序列化 | `060003EA` / `0x68D20` | 先调用 `InitParam` 将数组填为 `FF`，随后按固定地址放置信道、VFO、广播、设置、联系人、APRS、消息、开机图、频段等数据 |
| 字节数组初始化 | `060003E6` / `0x68AF4` | 按数组长度循环写入 `0xFF` |
| 打开菜单 | `0600040B` / `0x6A290` | 文件筛选 `*.dat` |
| 打开文件 | `0600040D` / `0x6A340` | 按文件长度分配数组，直接读取文件，随后调用 `PareCpsData` |

这里没有序列化对象包、压缩层、加密容器、型号头或文件级校验和。文件中的配置地址与该版本编程数据的地址一致。原生打开器还允许按任意文件长度重分配数组；这不证明其他长度或其他型号有效。本项目只接受样本默认长度 `0xD7000`。

可用 `tests/reference/check-cps-dat.py` 对自行取得的原始样本重复核对：

```sh
python tests/reference/check-cps-dat.py /path/to/extracted-cps.exe
```

依赖 `dnfile`、`dncil`。脚本只读取 PE/.NET 元数据和 IL，不启动原厂程序，不加载 CLR，也不访问设备。核对结果见 [cps-dat.json](evidence/cps-dat.json)。

## 型号和覆盖范围

导入前必须明确确认文件来自 **UV-K10 Pro 官方 CPS 0.56**。长度、扩展名、文件名均不能单独认证型号；K8/K82/其他产品的数据不能凭“都是 DAT”互换。检测到 Cortex-M 应用向量头的输入会被拒绝。

导入后，工作区只声明 17 个配置区的覆盖范围，与当前编辑器需要的记录区域对应；文件剩余内容保存为独立的原始封套。文件中 `FF` 填充不被声明为实际读出的 NOR 内容，工作区也不会因此成为 4 MiB 完整转储。

除常规配置区，官方保存器还明确处理 `0x1B000` 的一个字节。它由 `GetUltraHighPowerFlag`（`060003EB` / `0x68E64`）写入文件，必须有读取或原文件来源才能生成完整 DAT。文件格式支持不会自动开放这个硬件相关字段的编辑权限。

## 无损保留和工作区保存

- 原 DAT 保存为固定长度的 Base64 封套，并附带 SHA-256。导入不更改字节，未修改时导出可逐字节还原原文件，包括未解释的区域。
- 编辑后导出：从通过校验的原始封套开始，仅覆盖当前配置区域。其他文件区域保持原样。
- 保存为 `.k10` 时，封套随项目保存；重新导入 `.k10` 时验证长度、类型、规范 Base64 和 SHA-256。封套只用于文件还原，不赋予型号、认证或设备会话身份。
- 从设备读取或其他工作区新建 DAT 时，要求所有必需配置区域均有覆盖。其他位置按官方保存器的行为初始化为 `FF`，并在导出前说明该行为。
- 缺少一个必需区域就拒绝导出，不把未读字段填零或凭默认值补齐。

SHA-256 的作用是检测文件封套损坏，并不是数字签名或厂商认证。

## 与官方 PC 再次打开、保存的差异

本项目 DAT 编解码保留底层存储字节，不假装消除了所有版本间的字段语义差异。比如，官方 CPS 0.56 的普通信道调制列表只有三项，参考固件 ENG 8.02.16 使用四项；含 SSB/CW 的 DAT 导出会提示这一差异，并保留字节，不自动改成其他调制。

官方 PC 的 `GetCpsData` 会从界面对象重新编码已知字段。它再次打开并保存文件时，可能归一化不认识的值或改变保留区；因此 `.k10` 仍是保留工作区基线、编辑值与覆盖信息的格式。

验证覆盖了固定长度限制、明确型号确认、MCU 误导入拒绝、配置覆盖隔离、原 DAT 精确往返、编辑后未知区保留、生成容器填充、缺失区域拒绝、封套校验和调制差异提示。尚未把生成的 DAT 交给 Windows 官方 CPS 运行验收，也未使用实机数据冒充测试样本。
